# Swim Constraints Lab

競泳コーチ・水泳指導者向けの、制約主導で練習課題を探す日本語Webアプリです。入力されたモード、技能領域、観察事実、レベル、用具などをもとに、成立・探索・実場面接続の3方向から課題を提示します。

## 方針

- AI、外部API、データベース、ログイン、永続的な履歴保存を使用しません。レッスン編集中の案と「元に戻す」の履歴は画面を開いている間だけ保持します。
- 課題選択は静的データと決定論的なロジックで行い、同じ条件には同じ結果を返します。
- 競泳108件、習い事水泳36件の合計144件を収録しています。
- すべての課題は「監修前の案」です。診断や唯一の正解、安全判断をアプリに委ねるものではありません。
- 実施前に、指導者が泳力・体調・水深・人数・施設ルールを確認してください。

## スタッフ用レッスン作成

トップ画面の「レッスンを組み立てる」から利用します。

1. 人数、レベル（初級・中級・上級・選手）、時間、使用コース数、狙い、練習内容を選びます。一般コースは50分が初期値です。
2. 「レッスン案を作る」で、導入・成立・探索・休憩・実場面・振り返りを配分します。既存の144課題と同じマッチング・静的調整ロジックを使います。
3. 活動名、時間、活動内容、距離・回数・休み、指導ポイント、準備、人数に合わせた進め方を編集できます。上下移動・削除・課題の入れ替え・活動追加にも対応します。
4. 「準備・課題の調整と入れ替え」から易化・難化等を反映できます。調整は課題の提案文に置き換えます。手で編集した文も含めて「元に戻す」「やり直す」で復元できます（直近60操作、連続入力は欄ごとにまとめます）。
5. 合計の超過・不足を確認し、必要なら「合計を○分に合わせる」で配分を調整します。配分には説明・移動・休憩を含みます。時間を合わせる操作は実施量や休憩の妥当性を保証しません。
6. スタッフが実施条件を確認してチェックすると、A4のレッスン案を印刷／PDFにできます。編集すると確認は外れます。確認しても課題は監修前の案のままです。

氏名等の個人情報は入力しません。案は練習選び・参考資料との画面移動では保持し、再読み込みやタブを閉じると失われます。必要な案は印刷／PDFで残してください。

### はまだスイミングスクールでの前提

- 15m × 3コース、幅約6.2m、水深1.1mを表示し、実際に使用できる1〜3コースを指定します。人数入力の上限60人は安全な定員や指導者数の基準ではありません。
- スタッフ画面では、飛び込み・長い水中移動・呼吸を制限する比較などを候補から除きます。1人または1コースのときは並走・隣レーンを必要とする案も除外します。元の144課題と既存の練習選びは変更していません。
- 25mプール向けの表記は、この画面でのみ25→15m、50→30m、75→45m、100→60mへ短縮します。既存の30m・60mは維持します。15mを超える距離は折り返しを含む合計として、折り返し地点・動線・実施量をスタッフが確認します。
- 頭数による組分けは進行のたたき台です。同時実施人数の判断ではありません。全員を見られる体制、立位や補助の必要性、休み、本人が選べる余地を確認してください。息止め競争は提案しません。
- 保存先・認証・DBは追加していません。本番公開や外部サービスとの連携は別途判断します。

## マッチングロジック

入力画面でレベル、狙い、局面・技能領域、今起きていること、用具を選ぶと、確認画面を挟まずに3方向の練習を表示します。モード、レベル、局面・技能領域を必須一致にし、狙い30点、局面・技能領域25点、観察事実20点、実施環境5点、用具5点、声かけ・変動設定5点で採点します。方向ごとに候補を分け、主制約の多様性、合計点、ID順で「成立・探索・実場面」を1件ずつ決定します。

候補が揃わない場合は、声かけ、フィードバック、変動設定、用具の希望、その他の詳細条件の順に任意条件だけを緩和します。モード、レベル、局面・技能領域、必須用具の有無は緩和しません。別案は順位付き候補を決定的に巡回し、難易度等の変更も乱数や文章生成ではなく静的な変更部品を適用します。

## ディレクトリ構成

```text
src/components/  画面コンポーネント
src/data/        144課題・選択肢・根拠・変更部品
src/engine/      決定論的な選択・変更ロジック
src/types/       データモデル
src/tests/       単体・データ・画面フローテスト
e2e/             Playwright実ブラウザテスト
docs/            コンテンツと根拠の運用方針
```

## 開発と検証

```bash
npm ci
npm run dev
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

開発サーバーは `http://localhost:5000` で起動します。PlaywrightのE2E確認は環境にブラウザがある場合に `npm run test:e2e` で実行できます。

## Replit

Previewは次で起動します。

```bash
npm run dev -- --host 0.0.0.0
```

Static Publishingの設定は、ビルドコマンドを `npm run build`、公開ディレクトリを `dist` としてください。

## 資料と課題の追加

課題は `src/data/competitiveTasks.ts` または `src/data/learnToSwimTasks.ts` に、既存の `TaskTemplate` 型と選択肢の文言に合わせて追加します。IDを一意にし、実施メニュー（やること・1回分・回数・休み）、成功条件、観察点、易化/難化・用具なし・大人数・実場面接続を具体的に記載してください。資料を追加するときは `src/data/evidenceSources.ts` に、タイトル、著者・組織、URL、支持する範囲、支持しない範囲、確認日を登録し、課題の `evidenceIds` から参照します。記載内容は資料が実際に支持する範囲を超えないようにします。
